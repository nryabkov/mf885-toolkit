# Редактор TTL — Community 0.4.7-dev.4 / основа 2.5.94

**На одном MF885 проверены чтение настройки, переключение 64 → Off →64 и
соответствующее изменение IPv4 UDP-трафика в обоих направлениях.** Проверка
выполнена 2026-09-07 после установки именно этой версии и сверки файлов.
Это экспериментальная версия для точной основы MF96 Ver.D / 2.5.94.
Длительная стабильность, совместимость со всеми MF885 и универсальное
восстановление после прошивки не подтверждены.

## Как пользоваться установленным интерфейсом

1. Подключитесь к MF885. На его обычном адресе управления откройте
   `/c047d4.html` и войдите с паролем управления. Ссылка Community extension
   есть и в штатном интерфейсе поддерживаемого образа.
2. Откройте **TTL**. Нажмите **Read router setting** — «Прочитать настройку
   роутера». Пока состояние не прочитано, изменение недоступно.
3. Выберите **64 · replace TTL** для подмены или **Off · stop replacing TTL**
   для отключения подмены. Off не выключает роутер и не задаёт пакету TTL 0.
4. Нажмите **Apply mode** один раз. Интерфейс проверит совместимость и текущее
   состояние, отправит одну запись и отдельно прочитает результат. Успех
   показывается только после совпадения подтверждения и повторного чтения.
5. Если исход неизвестен, не повторяйте запись вслепую. Дождитесь доступности
   роутера и нажмите **Read router setting**. Автоматического повтора нет.

Если значение уже выбрано, повторная запись не отправляется. Изменение состояния
другой сессией между чтениями блокирует запись. Используйте одну управляющую
вкладку: локальная блокировка не гарантирует защиту от одновременных команд
из других браузеров. Автообновление общих данных не читает и не меняет TTL.
Обычный вход читает состояние и предварительный список SMS; выбор списка
использует штатный POST, который не является отправкой SMS.

Настройка находится в оперативной памяти. Реализация задаёт 64 при загрузке,
сохранения выбора после перезапуска нет. В этом опыте отдельный перезапуск
после Off не выполнялся. Произвольное число в dev.4 не предлагается: доступны
только два проверенных режима. Нативный протокол версии
`r47-revision24-ttl8` отделён от Community-версии и версии штатной основы.

## Что означает TTL и что измерено

TTL — оставшееся число переходов IPv4-пакета. После подмены следующие
маршрутизаторы могут уменьшить его. Поэтому полученное на сервере 49 не означает,
что нужно выбрать 49. IPv6 использует другой механизм и в этот режим не входит.

В каждом направлении отправляли по два пакета с исходными TTL 32 и 96:

| Режим | От MF885 к серверу: TTL в точке приёма | Ответы к MF885: TTL на принимающем интерфейсе GL |
|---|---|---|
|64, первое чтение|49 /49|64 /64|
|Off|17 /81|16 /80|
|64, повторное включение|49 /49|64 /64|

Всего проверены шесть запросов и шесть ответов,24 кадра в четырёх точках захвата,
потерь захвата нет. В Off разница между исходными TTL сохранялась; после
включения64 значения снова выравнивались. Финальное отдельное чтение подтвердило
64, ревизию 2. Это повторяемое соответствие настройки и наблюдаемого поведения
проверенных IPv4 UDP-потоков. Оно не доказывает точное место нативного вызова,
TTL на физическом сотовом выходе, все протоколы/значения или работу при гонках.
Приём сервера подтверждён захватом кадров ОС, а не доставкой приложению UDP.

Настоящий браузер использовал неизменённые установленные JS/CSS через
ограничивающий запросы прокси; в проверенный HTML добавлялось только заполнение
формы входа из памяти и отключение автообновления. Это проверка редактора с
такой тестовой обвязкой, а не всех возможных сценариев входа. Сам интерфейс
работает на MF885 и не требует GL.iNet, VDS или облака.

После опыта временная маршрутизация очищена, проверочные процессы завершены,
шлюз и его автозапуск сохранены. В предшествующей доставке прошивки автоматическое
удаление временной маршрутизации завершилось ошибкой после смены интерфейса;
отдельная проверка восстановления подтвердила очистку и работу шлюза.
Этот результат не превращает механизм доставки в универсально проверенный.
Исторический R4.6 остаётся заблокированным; успешный dev.4 не меняет его вердикт.

## Исходники, тесты и сборка

[Шесть файлов интерфейса](../webui/0.4.7-dev.4/) сохранены побайтно из проверенного
образа. Их размеры и SHA-256 — в `manifest.json`. Это встроенный интерфейс,
не автономный сайт: API, авторизацию и библиотеку MD5 предоставляет MF885.
Копирование HTML/JS/CSS не устанавливает нативный компонент TTL.
[Описание исходников и архитектуры](../firmware/community-0.4.7-dev.4/README.md)
объясняет точные зависимости и ограничения. Инструкции старой R4.5 остаются
в [историческом руководстве](WEB_INTERFACE_RU.md).

Подготовьте собственную точную резервную копию и Base XML по
[инструкции сборки](BUILD_FIRMWARE.md). Перед сборкой подтвердите целевую
архитектуру всех нативных компонентов: ARMv5TE/Thumb-1, little-endian ARM EABI5,
без Thumb-2/NEON/VFP; профиль компилятора `thumbv5te-none-eabi` / `arm926ej-s`.
Сборщик проверяет исходные и полученные машинные байты; успешная компиляция
сама по себе не подтверждает совместимость устройства.

Для Linux x86-64 нужны Python 3.10+, зависимости `requirements.txt` и
`/lib/x86_64-linux-gnu/libLLVM.so.20.1`. Зависимости автоматически не устанавливаются.
После их подготовки, из корня репозитория:

```bash
mkdir -p out
python tools/mf885_build_variant.py \
  --variant community-0.4.7-dev.4 \
  --golden input/MF885_golden.bin \
  --identity-xml input/mf885-base.xml \
  --output-dir out \
  --acknowledge-brick-risk
```

Команда выполняет две сборки, сравнивает результат, проверяет 36 условий и
полный контейнер независимым инспектором. Готовый файл и отчёт остаются локально;
существующие результаты не перезаписываются. Сборщик не обращается к устройству
и не устанавливает прошивку. Файл привязан к вашим входным данным; образ другого
экземпляра использовать нельзя. Отчёты могут содержать отпечатки устройства —
не публикуйте их. Готовых прошивок и средств прошивки в этом репозитории нет.

Офлайн-проверки публичного дерева:

```bash
python -m unittest discover -s tests -p '*_test.py'
npm ci
npm test
```

Node 22 и linkedom 0.18.12 используются для 23 сценариев редактора, включая
неправильный ответ, несовпадение ревизии, потерянное подтверждение и отсутствие
повтора. Нативные тесты исполняют модель полученных Thumb-1 инструкций и
проверяют границы памяти, checksum и ABI. Проверки с собственными исходными
образами могут быть пропущены при отсутствии этих файлов; число пропусков
нужно сохранять вместе с результатом, а не считать такие проверки пройденными.
