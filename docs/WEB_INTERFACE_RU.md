# Веб-интерфейс MF885 Community R4.5

Это инструкция для встроенного в прошивку интерфейса **Community extension 0.4.5**. R4.5 установлена и проверена на исследуемом экземпляре MF885. Это экспериментальная версия: результат одного устройства не означает совместимость со всеми ревизиями, проверенную отправку SMS или длительную стабильность. Текущий статус и ограничения — в [RELEASES.md](RELEASES.md).

## Как открыть

Подключитесь к своему MF885 и откройте его обычный адрес управления, заменив путь страницы на **`/r45.html`**. Используйте адрес именно MF885, а не другого маршрутизатора между ним и компьютером. Ссылка **Community extension** также добавлена в штатный интерфейс поддерживаемого образа.

Введите пароль управления роутером в поле **Router password** и нажмите **Sign in**. До отправки формы приложение не обращается к API роутера; HTML, CSS и JavaScript при этом загружаются обычным браузерным способом.

Вход включает Digest-аутентификацию и проверку точных полей штатного `status1`: модель `LV01` или `MF885`, аппаратная версия `MF96 Ver.D`, версия основы `2.5.94_release_MF855_NZ_CP_2.129.003`. При несовпадении приложение останавливает вход. Эти поля проверяют поддерживаемую основу; сами по себе они не доказывают установку R4.5 и не являются проверкой серийного номера. Не отключайте проверку ради другой ревизии.

**Router settings / Open router settings** открывает штатную страницу `/index.html`. **Sign out** завершает локальную сессию расширения и останавливает его автообновление.

## Что находится на страницах

| Раздел | Назначение |
| --- | --- |
| **Home** | Сводка сети, батареи и последних сообщений; переходы к остальным разделам. |
| **Messages** | Входящие на устройстве, отправленные, сообщения SIM и черновики. **Load complete history** загружает полную доступную историю с ограничением числа страниц. **Cancel** отменяет чтение сообщений. |
| **Diagnostics** | Данные устройства, SIM, регистрации, батареи и питания. Показывает источник, свежесть и ошибки отдельных ответов. |
| **Modem** | Сведения о сотовой сети и радиосигнале из того же снимка, что использует Diagnostics. Справка отделяет наблюдавшиеся поля от полей схемы; отсутствующее значение не подменяется измерением. |
| **TTL** | Описание фиксированного TTL 64 для подходящих пересылаемых IPv4-пакетов. Редактирования значения, переключателя **Off** и запросов изменения TTL здесь нет. |

Diagnostics и Modem используют штатные `status1`, `wan` и `Engineer_parameter`. Раздел Modem не предоставляет командную консоль, изменение Engineering mode, перезапуск или управление прошивкой. Отображаемая длительность соединения не должна считаться независимо доказанным временем работы всего устройства.

## Автоматическое обновление

После успешного входа данные начинают загружаться автоматически. По умолчанию **Auto refresh · on** включает общий снимок состояния примерно каждые **30 секунд**, а первую страницу сообщений — каждые **60 секунд**. Занятая операция откладывает обновление; скрытая вкладка приостанавливает планирование новых запросов. Возвращение к вкладке возобновляет обновление.

Нажмите **Auto refresh · off**, чтобы отключить его. Предпочтение сохраняется в сессии вкладки. **Refresh all** вручную обновляет общий снимок и предварительный список сообщений. Чтение сообщений использует предусмотренную штатным API команду выбора списка; его нельзя описывать как исключительно HTTP GET.

Страница TTL сама не отправляет TTL- или diagnostic-команды; общий опрос состояния может продолжаться, пока автообновление включено.

## Отправка и удаление SMS

**New message → Send once** выполняет одну попытку отправки после чтения исходной папки Sent. Допускаются номер из 3–15 цифр с необязательным `+` и текст до 268 символов BMP без emoji; это до четырёх UCS-2 сегментов. Возможна тарификация оператором. Интерфейс ищет новую соответствующую запись в Sent, но такая запись **не доказывает доставку получателю**.

Удаление доступно только для подходящей записи входящих после проверки полноты списка и идентификаторов, с отдельным подтверждением. Оно необратимо; интерфейс проверяет отсутствие удалённых идентификаторов в повторно прочитанной папке.

При **Outcome unknown** отправка или удаление могли уже произойти. Приложение блокирует новые записи и не повторяет действие автоматически. Сначала выясните фактическое состояние; перезагрузка страницы снимает локальную блокировку, но не доказывает, что безопасно отправить повторно. Эта публикация не заявляет проверку реальных SMS-операций на R4.5.

## Что показала проверка TTL

В одном ограниченном опыте на установленной R4.5 четыре исходящих пакета с TTL **32, 96, 32, 96** наблюдались на сервере с TTL **49, 49, 49, 49**. Четыре ответа с исходными TTL **32, 96, 32, 96** пришли на интерфейс GL с TTL **64, 64, 64, 64**. Это свидетельство выравнивания исходящего TTL на исследованном пути и наблюдение TTL 64 на принимающем интерфейсе GL.

Измерения выполнены в точках захвата операционных систем. Они не доказывают отдельно физический TTL 64 на сотовом выходе MF885, число оставшихся переходов или причинную роль конкретного исправления без сопоставимого контрольного опыта. Для четырёх исходящих кадров сервера метаданные ядра подтверждают ещё не завершённый checksum; у соответствующих принятых кадров полная контрольная сумма корректна. Полный набор кадров принят с этой оговоркой, а не как доказательство checksum на физической линии.

Опубликованные файлы интерфейса сохранены побайтно как в проверенном образе. Поэтому их исторический текст **live measurement is pending** не переписан после опыта. Актуальные результаты следует читать в [RELEASES.md](RELEASES.md).

## Исходники и воспроизведение

Три новых community-файла доступны в [webui/r4.5](../webui/r4.5/): [r45.html](../webui/r4.5/r45.html), [r45app.js](../webui/r4.5/js/r45app.js), [r45ui.css](../webui/r4.5/css/r45ui.css). Это исходники встроенного интерфейса, **не автономный сайт**. Библиотеку `js/library/md5.js`, API и сессию предоставляет штатный веб-сервер роутера. Открытие через `file://` или GitHub Pages не создаёт работающий интерфейс управления. Копирование этих трёх файлов также не устанавливает нативное исправление TTL.

Для воспроизведения используйте собственную совместимую резервную копию и локальный файл Base по [инструкции сборки](BUILD_FIRMWARE.md). Профиль [mf885_community_r45.py](../tools/mf885_community_r45.py) воспроизводит новые файлы из проверенных исходных записей WEBI и проверяет их размеры и SHA-256 через `ADDITION_OUTPUT_RECORDS`. Полный R4.5 builder собирает их вместе с нативным компонентом; опубликованные vendor-файлы для этого не требуются — они берутся из вашей копии.

Перед сборкой проверьте архитектуру и зависимости по [описанию R4.5](../firmware/community-r4.5/README.md): целевой нативный код — ARMv5TE/Thumb-1, little-endian, ARM EABI5, без Thumb-2 и невыровненных доступов. Из корня репозитория, после подготовки входов и зависимостей:

```bash
mkdir -p out
python tools/mf885_build_variant.py \
  --variant community-r4.5 \
  --golden input/MF885_golden.bin \
  --identity-xml input/mf885-base.xml \
  --output-dir out \
  --acknowledge-brick-risk
```

Полученный `MF885_Community_0.4.5-community-r2-native-r19-cafe-r2.bin` и отчёт остаются локально. Builder проверяет точную поддерживаемую основу и не перезаписывает существующий результат. Проверяйте итог независимым инспектором по инструкции сборки; успешная сборка не заменяет проверку совместимости и восстановления. Готовый firmware binary и автоматический инструмент прошивки в эту публикацию не входят. Команда выше не обращается к роутеру и не устанавливает прошивку; образ привязан к предоставленному экземпляру и не предназначен для другого устройства.

## Приватные данные

В статических community-файлах нет сохранённых паролей, SMS или идентификаторов экземпляра. Однако текущий JavaScript выводит **полные ответы роутера в консоль браузера**. Консоль, HAR, снимки экрана и локальные отчёты могут раскрывать сообщения, телефонные номера, идентификаторы SIM/устройства, адреса и параметры сети. Не публикуйте их без проверки и удаления приватных значений. Резервная копия и `mf885-base.xml` также должны оставаться приватными.
