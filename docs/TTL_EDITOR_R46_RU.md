# Редактор TTL в R4.6

**Проверка на устройстве 2026-09-06 не пройдена. Не используйте редактор R4.6
и не повторяйте запрос чтения TTL.** После успешной установки и проверки файлов
первый запрос состояния получил ноль байт ответа до тайм-аута; затем изменилась
USB-топология. Роутер восстановился автоматически, но причина сбоя ещё не
установлена. Изменение TTL и Off не проверялись. Общий сборщик блокирует R4.6.
Исходники и прежние хеши сохранены для анализа; индивидуальный исторический
сборщик остаётся исследовательским инструментом, а не обходным путём установки.
После этого исторического сбоя выпущены исходники [0.4.7-dev.4](TTL_EDITOR_047D4_RU.md),
где чтение,64/Off/64 и ограниченные двунаправленные UDP-наблюдения прошли проверку.
Это не снимает блокировку R4.6 и не является общей гарантией для чужих устройств.

Следующее описание сохраняет задуманный интерфейс и его ограничения.
Это описание эксперимента, **не инструкция к выполнению на R4.6**.

[Исходники интерфейса](../webui/r4.6/) предназначены для штатного веб-сервера
MF885 с нативными обработчиками R4.6. Нужны обычная авторизация и точная проверка
совместимости устройства. Облачный сервер, GL.iNet или VDS для работы редактора
не требуются.

1. Откройте раздел TTL и нажмите «Прочитать состояние». Кнопки изменения откроются
   после двух ответов, подтверждающих свежесть состояния обработчика.
2. Введите целое число от1 до255 без знака, пробелов и ведущих нулей. Значение64
   — исходное в экспериментальной сборке, а не универсальный совет для оператора.
3. Нажмите «Применить». Интерфейс проверит текущее состояние, отправит не более
   одной записи и прочитает результат. Сообщение об успехе требует подтверждения
   фактического значения в новом ответе.
4. «Выключить подмену · Off» отключает изменение TTL этим обработчиком. В поле
   числа не нужно вводить0. Проверка Off на реальном трафике пока не выполнена.

Если запись могла уйти, а связь оборвалась, результат показывается как
неизвестный. Автоматического повтора нет. Сначала прочитайте состояние вручную,
затем решите, нужно ли новое изменение. Введённое, но не отправленное число
сохраняется при обновлении данных. Периодическое обновление других разделов
не читает и не меняет TTL.

TTL — запас переходов для пакета IPv4. Значение на принимающем сервере может
быть меньше: наблюдение49 не означает, что следует вводить49. Малые значения
могут нарушить доставку. Обработчик относится к подходящим пересылаемым IPv4
пакетам в обоих направлениях; локальный трафик и IPv6 не входят в этот режим.
Чтение состояния не измеряет TTL на физическом сотовом выходе.

Настройка хранится в оперативной памяти. Сохранение после перезапуска не
реализовано, а отдельные виды перезапуска ещё требуют проверки. В консоль R4.6
попадают только ограниченные метаданные запросов; полные ответы роутера и
произвольные объекты ошибок исключены. В опубликованной R4.5 прежняя политика
логирования сохранена вместе с её точными исходниками.

Архитектура, ограничения и офлайн-проверки описаны в
[техническом описании R4.6](../firmware/community-r4.6/README.md).
